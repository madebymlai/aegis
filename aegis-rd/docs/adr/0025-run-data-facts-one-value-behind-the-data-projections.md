# Run data facts: one value behind the data projections

ADR-0015 rejected an ambient `RunContext` but recorded a revisit trigger: the co-traveling trio `data_result` + `array_contract` + `metric_registry_fingerprint` are all facts about what data this Run ran on, and if they kept co-travelling they would become a domain-named module adjacent to what `run_data_contract.py` assembles. That trigger is now active — the pair crosses the orchestrator, the data metadata artifact writer, setup's evidence baseline, publishing's candidate identity (twice: rows and store provenance), and completion's artifact payload, with the fingerprint riding alongside at every stop. This ADR cashes the trigger in.

`run_data_contract.py` deepens in place: it gains a frozen `RunDataFacts` value with three public fields (`data_result: MarketDataResult`, `array_contract: DataArrayContract`, `metric_registry_fingerprint: str | None`) and three projection methods — `evidence_payload()` (was `build_run_data_evidence_payload`), `candidate_data_identity()` (was `build_candidate_data_identity`), and `metadata_artifact_payload()` (absorbed from `provenance/data_artifacts.py`, where `to_builtin(data_result.metadata) | array_contract.metadata()` was a fourth home for the pair's schema knowledge). The free functions are deleted, not shimmed (Forward-First). Fields stay public: the module is a record of facts, and the fingerprint is consumed as a bare value inside three payloads. The schema-version strings (`candidate_data_identity.v3`) and the adjustment-mode fact stay implementation.

The facts value is born by composition, after load: the orchestrator constructs it in one line immediately after `load_market_data_result` returns. The contract's pre-load life is real and stays untouched — `build_run_data_array_contract`, `RunEvidence(data_arrays=array_contract.metadata())`, and the `assert_configured()` gate all run before any data exists, and the assert must fire after the recorder starts so failures are recorded as failed Runs. Making the facts module own loading would force the recorder or the evidence ledger into its interface — exactly the ambient-authority coupling ADR-0015 closed.

Ownership stops at the pure projections. `build_candidate_store_provenance` and `build_strategy_artifact_payload` take `facts` as one parameter but keep their homes: the former mixes in `recorder.run_id`, the optimization source, and config; the latter is a whole-run projection with strategy evidence, preflight, execution, and candidates. Folding them in would name the module after a slice of what it does. Consumption follows ADR-0015's rule — every consumer reads at least two of the three fields via a projection, so `run_pipeline_setup`, `run_pipeline_publishing`, `run_pipeline_completion`, and `write_data_metadata_artifact` all take `facts` whole, and the threaded trio disappears from their signatures. `SetupResult` is unchanged: facts is an orchestrator-owned input identity, not a setup product, threaded like `config` and `recorder`.

Landing is one step. ADR-0015 needed two because it curated fields while naming them; here the three fields were named by ADR-0015 itself and no computation moves except one pure payload expression. The oracle is the house one: `manifest.json` and `strategy_run.json` byte-identical, no golden updates — any golden diff is a bug in the refactor. `tests/support` gains `make_run_data_facts(**overrides)` beside `make_setup_result`; the nine contract tests migrate mechanically from free functions to methods with the same fakes and payload-key oracles; the metadata artifact payload gains a direct method test in the same file. Duck-typed fakes survive unchanged (tests sit outside mypy's `files = ["research"]`).

## Considered options

- **The full four-projection module** (the architecture review's sketch: Evidence, identity, Provenance, and artifact projections all internal): rejected — the provenance and artifact builders are mostly not data facts, and swallowing them makes a god module that fails ADR-0015's own naming rule, "named after the facts it owns."
- **Facts owns loading** (constructor takes config + contract, asserts, loads, returns facts): rejected — the pre-load contract and post-load facts are different lifetimes, and gluing them makes the interface carry the orchestrator's sequencing and its recorder coupling.
- **A new `run_data_facts.py` file, or renaming the module**: rejected — a new file splits one body of knowledge (the data-evidence schema) across two files that change together; a rename is churn across ~10 import sites while "contract" remains accurate for the pre-load half.
- **Keeping the free functions as delegating wrappers**: rejected per Forward-First — no caller needs them once signatures take `facts`.

## Consequences

- The trio threading collapses: three parameters become one at four call seams, `build_candidate_store_provenance` goes from six parameters to four, `build_strategy_artifact_payload` from thirteen kwargs to eleven.
- Every projection of the pair's schema — evidence payload, candidate identity, metadata artifact payload — lives in exactly one module; `provenance/data_artifacts.py` keeps the write (recorder coupling stays in provenance) but loses the payload knowledge.
- **Amends ADR-0015**: its revisit trigger is discharged; the bundle carries a domain name, the recorder stays outside the seam, and no stage gains ambient authority.
- `manifest.json` and `strategy_run.json` are byte-identical — the regression oracle for the whole change.
