# Components ship one candidate-batched callable; the wide/scalar split is deleted

The component contract carried two implementations of every component: a scalar `run` (per-candidate, pandas in/out) and a `wide_callable` returning a candidate-major array of shape `(n_rows, n_candidates × n_symbols)`. A survey of all 33 registered components found every `run_wide` is a loop over (unique) candidates around the same per-candidate logic — the two callables never diverged in capability, only in plumbing — so each component held two copies of its logic that could silently drift, policed by per-component wide-matches-scalar oracle tests. Meanwhile the production path used only the wide callable: the scalar was loaded into `_ComponentRuntime.callable` but never invoked, and its validators (`_coerce_indicator_outputs`/`_coerce_indicator_frame`, the per-candidate `ComponentStrategyInputs`) were dead. The wide path also validated nothing: `np.asarray(output)` with no shape check fed `window()` slicing that silently truncates a misshapen array, and a multi-output indicator would have every `output_name` aliased to the same array.

The split is deleted in favour of the branch production actually uses. A component ships exactly one callable: a module-level `def run` with the batched signature (`n_candidates`, `**param_lists`). The entry-point name is a fixed convention, not a declaration — `COMPONENT_CALLABLE`, `wide_callable`, and `param_space_callable` all leave the component file contract, since the rename freedom they granted served no component. The parameter space follows the same rule: a component has one iff its module defines `def param_space` (presence-detected in the AST walk registration already performs), so a manifest flag that could contradict the file never exists. The component file contract is exactly three things: the `COMPONENT_MANIFEST` dict carrying only domain facts (id, version, inputs, params, outputs, defaults), `def run`, and optional `def param_space`. With no scalar to contrast against, the "wide" qualifier is dropped everywhere: `WideIndicatorPrecompute` → `IndicatorPrecompute`, `WideComponentStrategyInputs` → `ComponentStrategyInputs` (replacing the deleted per-candidate dataclass), and the wide-prefixed helpers lose the prefix. Return contracts differ by family because output cardinality genuinely differs: an **Indicator** returns `Mapping[output_name → array]` — always a mapping, even single-output, since multi-output indicators are the norm — with keys validated against manifest `output_names`; a **Strategy** returns the bare allocation array, because the glossary defines a Strategy as emitting a single signed target-weight frame and `StrategyManifest.output_name` is singular. The framework gains a fail-closed shape gate at the precompute/simulate boundary — each returned array must be exactly `(len(close), n_candidates × n_symbols)`, raising `ComponentSourceError` naming the component, expected, and actual — because with components hand-rolling block layout this gate is the only barrier between a layout mistake and silently wrong candidate blocks. `COMPONENT_OPTIMIZATION_SOURCE_SCHEMA_VERSION` bumps to `.v2`.

The deleted scalar oracle is replaced by a framework-provided **self-consistency oracle**, runnable generically for any registered component: `run` over the full candidate batch must equal stitching `run` invoked per single-candidate batch. This catches the failure class the scalar oracle caught (block misplacement, parameter broadcast errors) with zero extra component surface, and unlike the scalar oracle it cannot go vacuous when both callables share a formula helper. It also enforces a contract the framework previously assumed silently: **candidate independence** — dedup expansion is sound only if equal param tuples produce equal blocks regardless of batch composition, which is exactly batch-vs-single equality. Equality is **bitwise** (`np.array_equal(..., equal_nan=True)`), not tolerance-based, and that strictness is the contract, not a test convenience: the same Candidate is recomputed under different batch compositions in normal operation — the full grid in the selection phase, three representatives in the held-out phase, a single candidate under a Lock re-execution — so any batch-dependent float drift (e.g., reduction-order differences in a cross-candidate-vectorized implementation) would make the same parameters yield different values across phases and break Candidate reproducibility (ADR-0006). A future vectorized component must preserve bitwise batch-invariance (vectorize across time/symbols freely; keep per-candidate reductions batch-size-independent) or it cannot be a Component. The oracle runs as a single registry-driven parametrized test over the **fixture components** in `tests/fixtures/components/` against small synthetic data — never over the experimental artifacts in `research/components/`, which CI must not depend on (ADR-0011: oracles are tests, never Run machinery or Evidence). The no-lookahead prefix-equivalence oracle (`validate_precompute_no_lookahead`) is unaffected and still guards causality.

## Considered options

- **Invert instead: components ship only a per-candidate scalar, the framework owns dedup + candidate loop + block layout.** Rejected. It moves the candidate-major layout decision into one module (Information Hiding) and makes shape correctness true by construction, but buys this with a permanent framework adapter layer and a second notion of component inputs — while components are disposable, machine-generated experiment artifacts whose internal duplication costs little. It also forecloses genuine cross-candidate vectorization, which the batched contract keeps open without any framework change.
- **Keep the dual contract, add a shape gate** (delete dead narrow helpers only): rejected — it enshrines two implementations per component and the oracle tests that exist only to police them.
- **Mapping-required-only-for-multi-output indicators** (bare array allowed for single-output): rejected — two return shapes is a permanent dual contract on a contract surface; forward-first picks one shape.

## Consequences

- Components are experimental artifacts (forward-first): existing ones fail to load until regenerated against the v2 contract; no compatibility shim, no dual manifest reading.
- Accepted: execution-level reproducibility under ADR-0006 breaks across the contract boundary — a Lock referencing a pre-v2 Run cannot re-execute until its components are regenerated. Evidence and component source hashes still audit what the original Run did.
- Accepted: the candidate-major block layout remains knowledge each component implements (`result[:, ci*n_symbols:(ci+1)*n_symbols]`), guarded by the shape gate and the self-consistency oracle rather than centralised. Revisit trigger: if components stop being disposable or layout changes are contemplated, the rejected inversion is the known alternative.
- The multi-output aliasing bug becomes unrepresentable (mapping keys are validated per output); the unvalidated-shape gap closes at the boundary.
- Dead code deleted from `component_source.py`: the `_ComponentRuntime.callable` field and its `load_attributes` entry, the per-candidate `ComponentStrategyInputs`, `_coerce_indicator_outputs`, `_coerce_indicator_frame`. The per-component wide-vs-scalar oracle tests are deleted with the scalar.
