# Market data exposes one Array interface (the Bundle), with a typed market_data.v3 metadata model

A **Component** (an **Indicator** or **Strategy**) reads the prices a **Run** loaded as **Arrays** — `Close`, `Open`, and any adjacent series it declares. Before this work the seam serving those Arrays was doubled, mis-named, and sat on a bloated wire artifact:

- **Two types both exposed feature access.** `MarketDataResult` (the loader's pre-validation output) and `MarketDataBundle` (the post-validation, Component-facing view) each defined `.feature()`, each re-implemented the "was this Array loaded?" guard, and `MarketDataResult.feature` existed only to be captured as the Bundle's `feature_getter` closure. The Bundle also carried a `native_data` field nobody read and a `loaded_features` set duplicating `metadata["loaded_arrays"]`.
- **The vocabulary was split.** The contract layer said **Array** (`OHLCV_ARRAYS`, `required_arrays`, `loaded_arrays`, `array_contract`); the accessor said `feature` (`.feature()`, `feature_from_ohlcv`, `OHLCV_FEATURES = OHLCV_ARRAYS`). CONTEXT.md listed `feature` under *Avoid*; the API could not tell a maintainer the canonical noun.
- **The split was fossilised in the metadata.** The `market_data.v2` **Evidence** artifact was a ~30-key untyped dict with literal duplicates (`provider_class == native_class`, `canonical_features == loaded_arrays`), eight overlapping Array-name lists, derivable fields (`unavailable_arrays`, `shape` counts), echoed loader config, and a vestigial `cache_policy` constant. It was read downstream via `.get()`, so drift was undetectable. ADR-0005 had deliberately left it untyped ("the dict *is* the wire contract").

We decided: `MarketDataBundle` is the single Component-facing **Array** interface, the entire Python surface is renamed from `feature` to **Array** with no alias, and the terminal metadata becomes a typed, facet-shaped `market_data.v3` model — accepting a one-time **Candidate Store** re-baseline rather than carrying a compatibility shim. **This amends ADR-0005**, reversing its untyped-metadata choice. As built:

- **The Bundle is an eager value object**: a `dict[str, DataFrame]` of materialised Array panels with one guarded accessor — `bundle.array(name)`, fail-loud on a dict miss ("not loaded for this run"). The loaded-guard *is* dict membership; `feature_getter`, `native_data`, `loaded_features`, and the unread `metadata` field are gone. `MarketDataResult` stays the pre-gate loader output (native data + metadata + diagnostics + quality, gated by `assert_usable()`) but exposes no Array access — the usability gate divides the two types. The Result→Bundle builder lives with the panel mechanics (`panels.py`), materialises every loaded Array up front, and fails loud if a declared Array cannot panelise.
- **The resolver is pure.** `array_from_ohlcv` resolves over native data / frames with no usability guard and no container-type branch, so the resolver module no longer depends on the container types.
- **The surface speaks Array, wholesale.** `bundle.array(name)`, `array_from_ohlcv`, `DataArrayDiagnostics`, `LOGICAL_ARRAYS`; the `OHLCV_FEATURES` alias is deleted (`OHLCV_ARRAYS` is the single source); every Component, guide, example, fixture, and test moved — **no back-compat alias** (Forward-First). **Array** is minted in CONTEXT.md.
- **The metadata is typed, facet-shaped `market_data.v3`.** Frozen pydantic dataclasses (`@pydantic_dataclass(frozen=True, config=ConfigDict(extra="forbid"))`, the ADR-0012 idiom): a `request` facet (source/symbols/timeframe/authored arrays), one `arrays: [ArrayDescriptor{name, required, loaded, observed, ohlc}]` descriptor list replacing the eight name-lists, `coverage` (symbols/rows/start/end), `quality`, `diagnostics`, and `provenance` (deduplicated provider/source blobs, index evidence, omitted fields). The `quality` and `diagnostics` facets are the observe/judge domain types themselves (`MarketDataQuality`, `DataDiagnostics` with per-Array `DataArrayDiagnostics`, one uniform shape whether or not an Array was available) — the dataclass field set is the wire shape, with no hand-rolled `to_metadata` serializers to drift. Dropped outright: `canonical_features`, `native_class`, `unavailable_arrays`, the `shape` counts, `cache_policy`. Serialisation stays on `to_builtin` / **Canonical Form** (ADR-0003): key-sorting makes field order irrelevant, so the typed model is hash-stable by construction.
- **The Candidate Key projection moved with it (R1).** `build_candidate_data_identity` reads the typed v3 facets — no `.get()` over an untyped dict — and emits `candidate_data_identity.v2`. Every new **Candidate Key** changed; the **Candidate Store** was re-baselined.

## Considered options

- **Collapse `MarketDataResult` and `MarketDataBundle` into one type**: rejected. The usability gate between "may be unusable" and "guaranteed usable" is load-bearing — one type would let Components pull panels off pre-validation data that never passed `assert_usable()`. The duplication was in the *accessor*, not the type split; removing Array access from the Result dissolves it.
- **R2: a projection-preserving shim so old Candidate Keys keep resolving**: rejected (Forward-First). The shim would be a permanent legacy projection re-deriving v2-shaped identity from v3 facets — exactly the kind of compatibility layer this codebase declines to carry. A one-time, recorded Store re-baseline is cheaper than a forever-maintained translation.
- **Freeze `market_data.v2` and rename only the Python surface**: rejected. It fixes the vocabulary but leaves the bloated, untyped, `.get()`-read dict in place — the fossil that caused the split to persist. The artifact is the part future Runs depend on; it had to be the part that got the redesign.
- **A pydantic `BaseModel` or a plain stdlib dataclass for the metadata**: rejected. `BaseModel` is not a dataclass, so `to_builtin`'s generic dataclass walk (ADR-0003) would need a parallel encoder path; a plain dataclass validates nothing at construction. The frozen pydantic dataclass with `extra="forbid"` (ADR-0012's config idiom) gets construction-time drift detection *and* rides the existing canonical serializer.

## Consequences

- **The Candidate Store re-baseline is an explicit, accepted reset.** Pre-v3 published **Candidates** are unreferenceable by their old Candidate Keys and pre-v3 **Locks** no longer resolve. No translation tool exists by design; dependent Runs/Locks are refit forward. Old persisted artifacts still say `features` and `market_data.v2` — that is history, not drift. **Do not "fix" it by reintroducing a shim or alias**: the code reading `Array` against old metadata saying `features` is the recorded cost of the rename, paid once.
- The metadata, run-manifest, and candidate-identity golden-bytes tests were re-pinned once (the recorded hash movement); they remain the regression guard for the v3 shape.
- Schema drift is caught at construction: an unexpected field on any facet raises at `describe` time instead of surfacing as a silently divergent dict; a drift test pins this.
- The eager Bundle moves Array materialisation errors from first access to Bundle construction — intentional fail-fast, covered by the market-data contract seam.
- ADR-0005's observe → judge → describe decomposition, the `MarketDataAdapter` seam, and the Lock scalar format are untouched; only the terminal artifact's typing (and the noun) changed. ADR-0005 is amended to mark its untyped-metadata option reversed under this ADR.
- The facet shape follows the structural lessons of Frictionless Table Schema, OpenLineage dataset facets, and DCAT (one field-descriptor list; facet separation; no derivable keys), with catalog-only concerns (titles, licences, URIs) intentionally omitted.
- **The "single Component-facing Array interface" was only single *inside* research; a structurally identical `MarketDataBundle` also lived in the kernel (`aegis_runtime`), and the Execution-Bundle seam duck-typed between them.** Root [ADR-0006](../../../docs/adr/0006-canonical-array-value-object-in-the-kernel.md) finishes this intent across the research↔execution seam: the kernel copy is canonical, research's copy is deleted and re-exported through the `aegis_research.data` facade, and the accessor's fail-loud message becomes the context-neutral `"...was not supplied"` (the research-only "...not loaded for this run" recorded above is superseded). The dict-membership invariant is unchanged.
