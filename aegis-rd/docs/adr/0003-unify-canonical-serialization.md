# Unify canonical serialization into one leaf module

Deterministic, hash-stable serialization was duplicated across several sites — `secrets.to_builtin`, a `manifest`-local `_to_builtin`/`canonical_json_bytes`, `candidate_store`'s JSON dump, and the inline `sha256[:32]` token hashes in `lock_resolution` and `evidence` — with two `to_builtin` twins and two diverging byte conventions (tokens: compact/strict/no-newline; the Manifest/Evidence content hash: trailing-newline/non-strict). Since a **Run**'s product is reproducible, hashed **Evidence**, that **Canonical Form** rule is load-bearing and must live in exactly one place.

As built, the rule lives in a leaf module `research/aegis_research/canonical_json.py` (stdlib + numpy/pandas duck-typing only; imports nothing from `configuration`/`provenance`/`optimization`). It exposes `to_builtin` — dataclass-aware, `ResolvedRunConfig`-aware, and unwrapping numpy scalars via `.item()` — and `canonical_json_bytes`, which is `sort_keys=True`, compact `(",", ":")` separators, `allow_nan=False`, and **no trailing newline**, so the one canonical form is unconditionally strict. `manifest`, `config`, `configuration.secrets`, `market_data.contracts`, and `configuration.resolution` all call through it; `manifest`'s former local `_to_builtin`/`canonical_json_bytes` are gone and `atomic_write_json` now serializes via the leaf.

Stable-ID hashing layers on top in a second small module, `optimization/canonical.py`, which exposes `canonical_digest(value, chars=32)` and `mint_canonical_token(prefix, value)` over `canonical_json_bytes`. `lock_resolution` mints `lock_` tokens and `evidence` mints `cand_` tokens through it, and `candidate_store._json_dumps` is a one-line decode over the same `canonical_json_bytes` — so every persisted byte-recipe now routes through the single rule. The schema-versioned **Candidate** identity canonicalizer (`candidate_identity.v2`) stays in `optimization/evidence.py` as a consumer of the token minter — it is a distinct, versioned contract whose reason to change is "what a Candidate identity *is*," not part of the serialization primitive.

The single forced byte change is placed on the **Manifest**/**Evidence** content serialization, not on tokens: the unified `canonical_json_bytes` adopts the compact, strict, newline-free form, so existing `lock_…`/`cand_…` tokens reproduce byte-for-byte and the CandidateStore is untouched, while the Manifest/Evidence content bytes lose their former trailing newline and gain strict NaN handling — a forward-first manifest/evidence change (no migration, per ADR-0002's precedent).

## Considered options

- **Change the token convention instead** (unify onto the Manifest trailing-newline): leaves exactly one encoding, but re-keys every **Candidate** and orphans every persisted **Lock** — a `lock_id` in a **Run Config** would stop resolving against an existing CandidateStore. Rejected: a Manifest is immutable per-Run, so changing its bytes only affects new Runs, whereas tokens are long-lived references.
- **Keep two byte recipes** (don't unify the framing): zero byte change, but preserves the very duplication we set out to remove — two `sha256`-over-sorted-JSON recipes free to drift again. Rejected as not actually deepening.
- **An extensible Encoder/Codec registry** with pluggable per-type encoders and JSON styles: maximally open-closed, lets both conventions coexist as configurations with no byte change, but only two codecs and two token schemes exist today — the machinery is unexercised (YAGNI). Deferred until a second identity version (`candidate_identity.v3`) actually lands.
- **A `Canonical` value object** with byte-identity equality and first-class `CandidateKey`/`LockToken` types: strongest test surface and honors No Primitive Obsession, but adds `.builtin`/`str()` unwrap ceremony at every evidence-embedding site and re-typing across the lock seam. The token types are deferred as a separate follow-up; the testing insight (golden-bytes tests pinning token output) is adopted without the wrapper.

## Consequences

- New leaf module `research/aegis_research/canonical_json.py`; `config.to_builtin` and the former `manifest.canonical_json_bytes` become re-exports / thin call-throughs so the ~30 `to_builtin` callers don't move.
- `to_builtin` handles dataclasses, so the `to_builtin(asdict(x))` sites simplify to `to_builtin(x)`; non-finite floats serialize as `null`.
- Manifest/Evidence content bytes change (compact, strict, no trailing newline); forward-first, no migration — old Manifests keep their recorded hashes and stay valid, only new Runs emit the new bytes. CandidateStore framing and `candidate_identity.v2` are unchanged, and `lock_…`/`cand_…` tokens reproduce byte-for-byte.
- Golden-bytes tests pin the current `lock_…`/`cand_…` token bytes as the regression guard that proves the refactor froze identities.
- Introduces the **Canonical Form** term (added to `CONTEXT.md`).
- Structural divergence from this ADR's original draft, recorded here as the as-built shape: the leaf is `canonical_json.py` (not `canonical.py`), and the stable-ID primitive shipped as `mint_canonical_token` / `canonical_digest` in `optimization/canonical.py` (not as `stable_id(prefix, payload)` in the leaf) so the leaf stays free of any `sha256` concern and `optimization` owns its token vocabulary. Thin re-export shims (`optimization/canonical_json.py`, the `optimization/canonical.py` re-exports) keep optimization-local import paths stable.

## Amendment (2026-06-11)

The `lock_` token and `lock_resolution` were later retired (a **Lock** now resolves through `candidate_rankings`; see CONTEXT.md ¶**Lock**). That left `mint_canonical_token` with a single consumer — the **Candidate Key** in `candidate_evidence` — so the token recipe was inlined into `_candidate_key` there and the `optimization/canonical.py` shim was deleted. The one-rule byte recipe in `canonical_json.py` is unchanged; Candidate Keys still reproduce byte-for-byte (golden pin in `test_optimization_candidate_evidence.py::test_candidate_identity_golden_bytes_pin`).

## Amendment (2026-06-11) — registry fingerprints join the one rule

Two byte-recipes still bypassed the leaf: the **component** and **metric** registry fingerprints each hashed through a local `json.dumps(..., default=str, separators=(",", ":"))` rather than `canonical_json_bytes`. The component registry compounded this — its public snapshot and its fingerprint were two hand-built encodings of one declaration. `_definition_public_snapshot` projected the *typed* manifest fields, while `_registry_fingerprint` hashed the raw author literal (`ComponentManifest.payload`), and a test factory re-implemented the fingerprint recipe verbatim to stay byte-identical. Three projections of one truth, none sharing code.

Collapsed onto a single projection. `ComponentDefinition.public_snapshot()` is now the one projection — it lives on the definition, not the manifest, because the fingerprint covers definition-level facts (`source_hash`, `has_param_space`, the entrypoint) the manifest does not hold. Both the registry snapshot and the fingerprint consume it, mirroring how `MetricDefinition.fingerprint_payload()` already returns `public_snapshot()`. `ComponentManifest.payload` and `fingerprint_payload()` are deleted (the fingerprint was their only reader), and the private `_freeze` is promoted to a public `freeze_component_registry(definitions)` so the test factory delegates instead of re-deriving freeze-and-fingerprint — parity with `freeze_metric_registry`.

Both fingerprints now hash through `canonical_json_bytes`; the local `json.dumps(default=str)` recipes are gone, so every persisted byte-recipe in the tree routes through the single rule. For the all-builtin projection this is byte-identical to the old recipe in every valid case. As-built deviation from this amendment's original draft: a NaN/Inf default param is **normalised to `null`**, not rejected — the leaf's `to_builtin` maps non-finite floats to `null` (per this ADR's Consequences) before `allow_nan=False` can ever fire, so fail-loud was unreachable at the leaf, and making the registries stricter than Manifest, Evidence, and Candidate-identity bytes would have split the one rule. The accepted cost is marginal: a `NaN` default and a `null` default fingerprint identically.

Forward-first re-baseline, no migration. `component_registry_fingerprint` and `metric_registry_fingerprint` are write-once Run **Evidence** — recorded in the resolution ledger, never recomputed-and-compared — so old **Manifests** keep their recorded hashes and only new Runs emit the new bytes, exactly the move this ADR made for Manifest/Evidence content. Both re-based together during the open re-baseline window. The new component fingerprint is at least as discriminating as the old: `public_snapshot()` is a superset of the prior raw-payload-plus-siblings recipe, and the manifest's `extra="forbid"` guarantees the typed fields lose nothing the literal carried. Golden pins: `test_metric_registry.py::test_default_registry_fingerprint_is_byte_stable` (unchanged — the leaf is byte-neutral for valid projections), a component fingerprint pin (`test_component_definition_queries.py::test_component_registry_fingerprint_golden_bytes_pin`), and a factory-vs-discovery equality oracle (`test_component_registry.py::test_factory_built_registry_fingerprint_equals_discovery_built`) proving the shared `freeze_component_registry` seam — not a hand-copied recipe — keeps the two build paths byte-identical.

## Amendment (2026-07-23) — Manifest v6 removes the artifact inventory

The Run Manifest is now the only persisted Run document, so it no longer inventories subordinate
artifacts. Manifest schema v6 removes the `artifacts` collection, its lifecycle states, path and
content-identity validation, and the `ArtifactRegistry` mutation façade. Canonical serialization
continues to govern the complete Manifest document; the golden oracle now masks only values that
remain volatile in that document.
