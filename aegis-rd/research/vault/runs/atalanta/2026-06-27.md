# 2026-06-27

## Correction

The first buy-hold-spread run below swept portfolio policy as optimization
candidate axes (`portfolio__band_up` / `portfolio__band_down`). That violates
the live/research contract: portfolio bands are global run/book policy, not
strategy-specific candidate identity. Treat the recorded sweep result as an
invalid transfer artifact. The config now fixes `portfolio.band_up=0.10` and
`portfolio.band_down=0.20`; a fresh fixed-policy run is required before any
promotion decision.

## Goal

Validate the buy-hold-spread execution idea on the definitive Atalanta EUR sleeve before it can
earn live use. The mechanism comes from [[trend-following-under-a-fixed-per-order-fee]]: make adds
harder than trims (`band_down > band_up`) so the sleeve pays fewer fixed-fee top-ups while still
cutting positions when the signal turns against them. This is an execution-shape test, not a new
signal test: universe, signal, strategy, costs, and ranking stay aligned to `atalanta/trend.yaml`.

Articles in scope: [[trend-following-under-a-fixed-per-order-fee]] for the buy/hold spread and
fixed-fee motivation, [[what-makes-a-trend-sleeve-convex]] for the convexity mandate, and
[[the-orthogonal-non-equity-trend-universe]] for the three-name non-equity substrate.

## Superseded Verdict - invalid portfolio-axis sweep

The best buy-hold-spread candidate clears the payoff threshold by the letter:
held-out `trend_convexity_payoff` **0.424** versus the pre-registered keep threshold **0.392**
and the current symmetric baseline **0.403**. The selection-to-held-out gap is negative, so this
is not an in-sample optimism artifact.

But it fails the other half of the keep gate: it does **not** reduce fills or reported fees. The
best asymmetric candidate uses **8.7** held-out trades and **27.48** total fees versus the symmetric
best's **7.7** trades and **24.61** fees. The payoff gain is real but bought with more execution,
which is the opposite of the fixed-fee buy-hold-spread thesis in
[[trend-following-under-a-fixed-per-order-fee]].

Decision: **do not promote from this run**. The result swept a global portfolio policy inside
Candidate identity, so it is useful only as a diagnostic hint that the fixed setting
`band_up=0.10`, `band_down=0.20` deserves a clean separate run. Anything pursued from here should
compare that fixed-policy config directly against the current symmetric 0.15 run above and must
include an explicit execution-cost budget.
