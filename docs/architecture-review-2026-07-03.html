Already deep — patterns to replicate

PR #71 deleted the bespoke store stack (~4,800 lines) and replaced it with the Nautilus Catalog + ContinuousContractModel. Three candidates from the 2026-07-02 review landed with it. The deepening below should extend these existing strengths, not import foreign patterns.

aegis-data

roll.py · liquidity.py

Pure roll-calendar and liquidity-leadership math behind 4–5 functions each. Interfaces are data shapes, never ports — the modules cannot know where data came from.

aegis-data

continuous_future.py · rebasing.py

Value object + a Rebasing protocol: the spread/ratio choice is made once, then propagated as a value. Byte-exact golden tests pin the whole Roll-Transition Table.

aegis-trader

domain core + RebalancePipeline

Allocator, Rebalancer, Sleeve Ledger: zero Nautilus imports, small interfaces, rich implementations. The pipeline is a port-injected orchestrator returning value objects.

aegis-trader

MarketDataPort · BookStatePort

Narrow protocols (6 + 4 methods) hiding all Nautilus cache reads. Domain-shaped, not Nautilus-shaped — the kernel stays at the edges (ADR-0003).

aegis-rd

Candidate Store · RunRecorder

Six methods hide schema versioning, transactions, and the publication lifecycle; highest earned fan-in in the system. RunRecorder is the single owner of Run state transitions.

cross-context

Execution Bundle seam · InstrumentId

Two adapters (entry-point registry + stub) make the bundle seam real. One identity — the Nautilus InstrumentId — crosses every seam with no translation layer (ADR-0007).

6 · An internal materializer seam inside the ContinuousContractModel

Worth exploring local-substitutable

After — state machine tells a materializer

ContinuousContractModel

↓ internal seam

Materializer

Problem — the model owns both the continuous-series state machine and a fragile six-module composition sequence; changing any collaborator means re-understanding _materialize_frame, and state transitions are only testable through the full chain.

Solution — give the implementation an internal seam: the model is constructed with a materializer and keeps only frame/front-leg/rebasing state and the roll trigger.

  • State machine tests need no chain
  • Composition tested once, in one place
  • on_bar roll path isolated
  • Interface unchanged for both consumers
ADR-0009 intact: the model stays the continuous-series owner — the seam is internal to its implementation.

Top recommendation

1 · Pin the market-data parity seam

Two adapters already share the ContinuousContractModel interface, and that interface is the test surface — yet nothing crosses it from both sides. Pinning it first is also the enabler: candidates 2, 6, and 7 all refactor behind this seam, and a parity suite makes each of them a safe, behaviour-preserving change instead of a leap.
