Problem

  • Deletion test passes: each stage cluster earns its keep

Two real adapters justify the seam: promotion.py also uses the codec
Problem

564 lines mixing two distinct responsibilities: parameter namespace encoding/decoding (used by both component_source.py and promotion.py) and pipeline assembly/validation. The namespace codec is a real seam — two adapters already use it — but it's buried inside the pipeline builder's implementation.

Solution

Extract the namespace codec (ref keys, param keys, slices, encode/decode) into optimization/component_params.py. The pipeline builder imports the codec's interface; promotion.py already does the same — formalizing the seam that already exists.

Wins
  • Two adapters justify the seam: component_source and promotion both use the codec
  • Locality: namespace encoding bugs concentrate in one module
  • Leverage: codec interface is small; implementation handles hex encoding, parsing, slicing
  • Tests isolate: test namespace round-tripping without building pipelines
✓ Both Strong candidates shipped

Run pipeline now has explicit stages, and Run Config validation is domain-split

The top recommendation — deepen the Run orchestration into stage modules — is done: strategy_runs.py became a ~193-line run_pipeline.py that sequences lock_resolution, candidate_publishing, run_artifacts, and run_data_contract. With explicit stages in place, the companion Run Config validation split also landed: a thin coordinator now dispatches to per-domain validators (base, components, data, optimization, metrics, portfolio), each independently testable.

Next — the two remaining "worth exploring" candidates: deepen reports into Metric computation + Evidence assembly and extract the Component parameter namespace codec. Both are lower-leverage; pick them up only when the reports module or the namespace codec next needs a change.
